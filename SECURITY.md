# Security Policy

## Supported versions

StrawIO VoiceChat is in Android foundation phase `0.1.x`. Security fixes are accepted for the current development branch until the first public release channel is defined.

## Reporting vulnerabilities

Report suspected vulnerabilities privately to StrawIO Studio maintainers. Include the affected version, reproduction steps, logs with secrets removed, and impact assessment. Do not publish exploit details until maintainers have had a reasonable remediation window.

## Security assumptions

- The APK may be reverse engineered.
- No master API secret, backend private key, database credential, plugin signing private key, admin key, or voice root secret may be placed in the client.
- Client-side anti-tamper checks are only defense-in-depth signals and are never the sole security control.
- Future backend authorization must verify server-side challenges, server allowlists, replay protections, protocol versions, and Play Integrity signals where appropriate.

## Secret handling rules

- Do not commit keystores, passwords, `.env` files, API credentials, generated credentials, or signing material.
- Use environment variables or untracked local files for release signing.
- Public URLs, protocol identifiers, public verification keys, and certificate pins with backup rotation may be shipped when needed.
- Private device keys are generated by Android Keystore and are non-exportable.

## No secrets in client guarantee

This phase is designed so the application contains no production secret. Future releases must preserve this property even if the APK is fully decompiled.

## Responsible disclosure

StrawIO Studio appreciates responsible disclosure and good-faith security research. Please avoid privacy-invasive testing, data destruction, service disruption, or access to accounts and systems you do not own.
